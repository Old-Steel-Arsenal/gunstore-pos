## `create_trade_in_intake`

`POST /api/method/ffl_core.api.trade_in.create_trade_in_intake`

**Auth (derived from code):** Roles: Sales User / Stock Manager / System Manager

Create a Used Firearm Item + FFL Acquisition for an individual trade-in.

With payload.apply_credit truthy, the acquisition is parked as a DRAFT
(booked at checkout submit) and the result carries `credit` — a locked
negative TRADE-IN-CREDIT line payload for the POS cart. Re-running the
dialog for a serial that already has a pending draft refreshes that
draft (new cost honoured) instead of duplicating it.

Without apply_credit the store buys the gun and pays the seller now:
payload.payout_method (Cash / Zelle / Check / ACH, and payout_reference
unless Cash) is required. The gun is received on a Purchase Receipt from
the seller, dated today, and the payment booked with it (Dr Stock Received
But Not Billed / Cr Cash or the bank) so the cash drawer count includes it
(_buy_now).

| arg | type | required | default | description |
|---|---|---|---|---|
| `payload` | — | yes | — | Trade-in intake fields (same shape as firearm_intake.create_intake plus seller identity and apply_credit) — dict or JSON string. |

**Returns:** {ok, item_code, acquisition}: with apply_credit from firearm_intake.create_intake (or _refresh_pending_draft), plus `credit`; without it from _buy_now (receive_goods._create_receive), plus `purchase_receipt` and `payout` ({entry, journal_entry}).

**Raises:** ValidationError: Missing fields / duplicate serial.

**Permissions:** roles.TRADE_IN_ROLES: the counter's sales role plus the stock roles; holding only the sales manager role is refused. Gated at entry, covering BOTH branches — the refresh branch (_refresh_pending_draft) rewrites A&D draft seller identity/cost and historically ran ungated (endpoint-gates hardening, 2026-08-07). A caller without a stock role files the gun under no Item (one is made for this gun) or an existing per-gun priced firearm Item (_check_counter_item); making or choosing any other Item stays a stock job. Everything behind the gate runs gate-free (firearm_intake.create_intake, receive_goods._create_receive), each of our writes with ignore_permissions; the ERPNext-internal checks against the session user (the gun's stock bundle) rest on the DocPerm setup/pos_compat.ROLE_GRANTS gives the counter.

## `seller_defaults`

`POST /api/method/ffl_core.api.trade_in.seller_defaults`

**Auth (derived from code):** Roles: Sales User / Sales Manager / Stock Manager / System Manager

Prefill for the POS Trade-in dialog's seller section.

A best-effort structured-name split of the Customer (generational
suffix pulled out even mid-name — 'pat lee IV Sampleton' →
first pat, middle lee, last Sampleton, suffix IV) plus their
primary address as a single line ('addr1, City ST zip' — the shape the
FastBound push parses). Everything is editable in the dialog; this only
saves retyping.

| arg | type | required | default | description |
|---|---|---|---|---|
| `customer` | string | yes | — | Customer name; unknown/blank returns {}. |

**Returns:** {source_first_name, source_middle_name, source_last_name, source_suffix, source_address_line1, ...} or {} when unknown.
