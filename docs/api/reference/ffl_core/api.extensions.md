## `inspect_upload`

`POST /api/method/ffl_core.api.extensions.inspect_upload`

**Auth (derived from code):** Roles: System Manager

Take an uploaded extension zip (multipart field ``file``), lint it, and describe it.

Nothing is installed: the zip is kept under the site's private files by
its sha256 until ``install_upload`` is called or it is replaced.

**Returns:** dict: the lint report (``ok``, ``findings``, ``permissions``, ``app_id``, ``title``, ``version``, ``publisher``…) plus ``sha256``, ``high_risk``, ``on_bench`` / ``installed_on_site`` / ``baked`` for that id, and ``upgrade``: None when the id is not on this server, else {"from", "to", "allowed", "reason", "permissions_added", "permissions_removed", "release_notes"} (the package's notes for versions after ``from`` up to ``to``, newest first, as one markdown text). An id whose last upgrade did not finish is not allowed until it is rolled back; ``reason`` says so.

## `install_upload`

`POST /api/method/ffl_core.api.extensions.install_upload`

**Auth (derived from code):** Roles: System Manager

Stage an inspected upload and hand it to the store's agent (background job).

| arg | type | required | default | description |
|---|---|---|---|---|
| `sha256` | string | yes | — | the upload reference returned by ``inspect_upload``. |
| `confirm_id` | string | yes | — | must equal the extension id — the typed confirmation ("you are installing unreviewed code"). The page's Update sends it itself (the manager confirms in its dialog). |
