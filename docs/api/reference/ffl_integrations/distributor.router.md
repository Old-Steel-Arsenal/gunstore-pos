## `update_order_ffl`

`POST /api/method/ffl_integrations.distributor.router.update_order_ffl`

**Auth (derived from code):** Roles: Purchase Manager / Purchase User / Stock Manager / System Manager / Distributor Console

Attach/replace the transfer FFL on a placed FDS order to release an FDS Hold

(the standard remedy the completion path calls for).

Re-validates the NEW licence through the SAME canonical chain routing uses
BEFORE calling the distributor: releasing a hold onto an expired or
address-incomplete FFL would defeat the very gate that held it, on a channel
with no cancel API. The resolved ATF record is pinned so the queue's expiry
display and any later disposition read one destination.

| arg | type | required | default | description |
|---|---|---|---|---|
| `do_name` | string | yes | — | Distributor Order name (a placed FDS order on hold). |
| `ffl_license` | string | yes | — | The new transfer FFL licence number. |

**Returns:** {"name": do_name, "ffl": ffl_license, "result": <distributor response>}.

**Permissions:** Distributor order/console roles (this gate is deliberately widened to the console role).
