## `m3_resync`

`POST /api/method/ffl_integrations.catalog_master.m3_resync`

**Auth (derived from code):** Roles: System Manager

Move the Items already on file onto the catalog master's categories (SPEC M3b).

Every enabled catalog Item that is not serialized is filed under its master
category (``Catalog Category``) and, where the tree names a group it may use,
that category's Item Group; its store products are re-categorised (category
only). Serialized Items, firearms and firearm groups are never moved; a legal
difference is listed, never applied. ``dry_run`` (default) changes nothing and
also lists what the category mirror would do on each store.

| arg | type | required | default | description |
|---|---|---|---|---|
| `dry_run` | integer | no | `1` | 1 (default) reports only; 0 applies the reported moves in a background job (the category mirror must be in Apply). |
| `token` | string \| null | no | `None` | Applying only — the dry run's ``token``. The plan is recomputed and must still be exactly the one the dry run showed, else nothing is done. |

**Returns:** {items: [{item, item_name, old_group, new_group, old_category, new_category, issues}], moves: {"old → new": count}, counts: {checked, catalog, changes, serialized_skipped, not_in_master, review}, stores: {site: {actions, issues, unlinked_terms}}, token}; applying adds queued: true (failures land in the Error Log, the rest go on) and re-baselines the product-changes cursor.

**Permissions:** System Manager.
