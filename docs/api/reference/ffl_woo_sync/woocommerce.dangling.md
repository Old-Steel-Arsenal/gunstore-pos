## `woo_audit_dangling_ids`

`POST /api/method/ffl_woo_sync.woocommerce.dangling.woo_audit_dangling_ids`

**Auth (derived from code):** Roles: System Manager

Audit stored Woo product ids for ones whose WC product was deleted (404).

Scans every connected store by default, and a store it cannot build a client
for is reported as skipped rather than aborting the run: letting the config
error out of here would 500 the request AND roll back any repairs already
made in the same transaction.

| arg | type | required | default | description |
|---|---|---|---|---|
| `fix` | — | no | `0` | Report-only by default; 1 (or True) nulls each dangling id and leaves a Comment + warning log. |
| `batch_size` | — | no | `50` | Clamped to 1..200; bounds each verification chunk — a fat-finger clamp on the parameter, not a rate limit; every candidate is checked. |
| `site` | — | no | `None` | Limits to one store — "retail", the only one (default: all). Any other value raises a ValidationError. |

**Returns:** { "checked": <int>,                 # ids verified against WooCommerce "dangling": [{"doctype","name","field","site","woo_id"}, ...], "fixed": <int>,                   # ids nulled (0 unless fix) "skipped": [{"site","reason"}, ...],   # stores with no usable client "counts": {"by_doctype": {...}, "by_site": {...}}, }
